# 可复用的 HTML 交互原则

## 目的

本文从两个现有 Web 界面中提炼可迁移到其他项目的交互模式。内容只描述界面结构、用户心智和反馈原则，不包含原项目的领域名词、字段、文件名或业务规则。

## 两类界面所呈现的模式

- **数据工作台**：以可检索、可筛选的表格作为主入口；行内状态帮助快速判断；选择多行后执行批量操作；复杂任务进入详情面板或分步审核。
- **任务工作台**：先让用户选择要做的任务，再进入专注页面；展示任务进度和输入来源；把机器生成结果放到人工审核环节；用户审核后再选取结果并导出。

这两种模式可以组合：用任务入口解释“从哪里开始”，用数据工作台支持“如何持续管理”。

### 参考仓库的 HTML 入口关系

`SmartVocabQuiz` 的 Web 界面有两个主要入口：`index.html` 是任务选择首页，用户从这里选择进入不同工作；`scan.html` 是词库工作台，用户在这里查看处理状态、添加输入并检索结果。另有 `quiz.html` 承载独立的审核与导出流程，是从任务入口进入的专用工作页面。也就是说，首页负责分流，工作页面负责完成任务，复杂流程可由独立页面承接。

## 首页字符层级与符号标记

以下取自参考仓库首页（`index.html`）及其共享样式，数值可作为新项目的初始标尺，需按实际字体和屏幕再校准。符号是文档中的视觉图例，不要求直接用这些符号作为页面字符。

### 字号层级

| 符号 | 字符角色 | 桌面字号 | 窄屏字号 | 用法 |
|---|---|---:|---:|---|
| `◆` | 首页主标题 | 40–61 px，随视口缩放 | 38 px | 首屏主要表达，一般控制在两行内 |
| `●` | 卡片标题 | 30 px | 27 px | 表达每个主要任务或功能 |
| `▲` | 正文说明 | 15 px | 13 px | 解释页面目标和卡片用途，行高约 1.8 |
| `■` | 操作按钮 | 12 px，粗体 | 12 px | 短动词标签，避免把说明塞进按钮 |
| `◇` | 状态/眉题/编号 | 10–11 px，粗体并增加字距 | 10–11 px | 作为辅助信息，与标题保持明显层级差 |

### 配色图例

| 符号 | 色彩角色 | 色值 | 典型用途 |
|---|---|---|---|
| `⬛` | 主文字 | `#183333` | 标题及主要正文 |
| `▧` | 次级文字 | `#526662` | 说明文字、辅助描述 |
| `🟩` | 品牌强调色 | `#087B70` | 标题强调、主要按钮、可交互重点 |
| `🟢` | 浅色强调底 | `#DFF3E8` | 状态徽标、轻量选中反馈 |
| `⬜` | 卡片表面 | `#FFFFFF` | 主要内容卡片 |
| `▱` | 页面底色 | `#F7F5EF` | 页面整体背景 |
| `🟨` | 次要暖色强调 | `#E6A943` | 次级任务入口、提示性装饰 |

**视觉顺序建议：** `◆` 主标题（`⬛`，重点词用 `🟩`）→ `●` 功能标题（`⬛`）→ `▲` 说明（`▧`）→ `■` 操作（`🟩`底白字）→ `◇` 状态信息（低对比辅助色）。用字号、字重、颜色和留白共同建立层级，避免只靠颜色传达含义。

### 图形符号与装饰语汇

首页卡片还使用了独立的图形符号与几何装饰。它们与字号/色值图例互补：图例里的符号用于标注设计角色，下面描述的是实际页面中的图形表达。

| 表示形式 | 截图中的表现 | 作用 | 复用规则 |
|---|---|---|---|
| `✦` / `✎` → 圆角方形徽章 | 卡片右上角的闪光、铅笔图标，各自放在浅绿或浅金底的约 `34 × 34 px` 方块中，图形约 `20 px` | 用一个易识别的形状提示卡片类别或操作气质 | 同一层级使用统一的徽章尺寸、圆角和对齐；图形可选文字字形、图标字体或 SVG，保持笔画风格一致 |
| `╱ hello` / `A B C` → 倾斜预览卡 | 卡片内的小型内容样片略微旋转，使用浅色底、细边框和轻阴影，样片内包含示例字符与小圆点 | 让抽象功能有一个可视化缩略预览，也为卡片增加视觉重心 | 样片只展示少量代表性内容；旋转和阴影用于装饰，不应影响文字阅读或点击目标 |
| `◯` → 环形轨迹 | 卡片背景后方的椭圆细线，部分超出容器边缘 | 建立柔和的空间层次并把视线引向卡片内容 | 采用低对比细线，置于内容下层，裁切在卡片边界内；不与文字和控件争抢焦点 |
| `●` → 小型暖色圆点 | 预览卡片一角的金色圆点 | 提供微小的色彩呼应和视觉收尾 | 作为装饰时尺寸小、数量少、位置稳定；若表示状态，则必须配有文字或其他可感知提示 |
| `↗` → 动作方向标记 | 主按钮末尾的外向箭头 | 暗示进入、前往或继续 | 只用于确有导航/推进含义的动作；图标与按钮文字间距统一，并确保按钮文字本身仍能说明动作 |

**图形符号的分工：** 有意义的功能图标应帮助识别入口或操作；预览卡、轨迹和点缀圆点负责氛围与说明。纯装饰图形不承担状态信息，关键状态也不能只用颜色或图形传达。若图标本身可点击，需要清晰的焦点、悬停和无障碍名称；若只是装饰，应从辅助技术阅读顺序中隐藏。

## 可迁移的交互原则

### 1. 先回答用户现在可以做什么

首页或页面顶部应说明当前空间的用途，并提供清晰的主要动作。若有多个相对独立的目标，用任务卡片或入口区分；若用户主要处理一批记录，直接进入列表并将主要操作放在工具栏。

**讨论点：** 新项目更像“从任务开始”还是“从数据列表开始”？是否需要两者兼有？

### 2. 主视图服务于扫描与定位

列表中的信息应支持快速浏览、搜索、筛选、排序或选择。重要状态应在列表层可见，完整内容留给详情区域。长文本可截断显示，并提供可访问的查看完整内容方式。批量操作应显示选择数量和作用范围。

### 3. 按复杂度分配交互空间

简单查看和轻量修改适合行内交互；需要比较上下文或多个对象时使用详情面板；有多个确认节点、内容较多或不可轻易撤回的任务适合专门工作区或分步对话框。对话框应有明确标题、主体、取消/关闭方式和主次动作。

### 4. 自动化提供建议，用户掌握最终决定

机器生成、匹配或校核的内容应标明其来源与状态，并让用户检查、修改、接受或拒绝。高影响操作应将“准备/预览”“人工核对”“最终执行”分开，避免把建议直接等同于已确认结果。

### 5. 让状态变化连续可见

界面应区分初始加载、处理中、成功、部分成功、失败和空结果。耗时任务显示当前阶段或进度；操作中禁用重复提交，并给按钮提供正在处理的文字。完成后给出结果摘要和下一步入口；失败信息应指出可采取的动作。

### 6. 高影响动作需要可预期的确认

删除、覆盖、发布、批量执行等动作，应在执行前说明影响对象、数量和结果位置或去向。能撤销的动作提供撤销或退回路径；难以撤销的动作需要明确确认。确认界面应准确说明后果，避免泛化的“确定吗”。

### 7. 保持任务上下文

完成操作后尽量刷新相关数据，并让用户回到结果所在位置。必要时清除与目标冲突的筛选条件、切换到相关视图、滚动并短暂标出新结果。跨页面或多步操作应保留用户已选内容和进度，除非用户明确取消。

### 8. 状态不能只依赖颜色

标签、图标、文字和颜色共同表达状态。状态词应简洁、稳定并可解释；对于机器判断，应提供来源或说明。悬停提示可补充细节，但关键说明不能只放在悬停状态中。

### 9. 用响应式布局保留核心任务

桌面端可使用多栏、宽表和密集工具栏；窄屏应重排内容、保留主要操作和状态，并让横向滚动或折叠行为可发现。复杂表格不应因缩窄而让关键控件难以触达。

### 10. 让界面可访问且可键盘操作

使用语义化的按钮、链接、标签和表单控件；为图标按钮提供名称；状态和进度使用辅助技术可感知的文本提示；模态窗口应支持键盘焦点管理和 Escape 关闭；焦点样式应清楚可见。

## 建议的通用页面骨架

1. **顶栏**：产品/空间标识、页面导航、全局服务或连接状态。
2. **页面说明**：当前目标、必要的简短说明、一个主要动作。
3. **概览区**：少量有助于决策的计数或摘要。
4. **工作区**：搜索/筛选工具栏与列表、卡片或编辑区域。
5. **详情与审核层**：检查上下文、修改内容、比较变更或逐项确认。
6. **反馈层**：内联校验、状态/进度提示、结果摘要与恢复路径。

不要求每个项目都显示全部区域；应按用户当前任务裁剪。

## 可复用的交互流程

```text
进入工作区
  → 选择或定位对象
  → 查看上下文与来源
  → 执行简单操作，或进入编辑/审核流程
  → 检查自动生成或即将产生的结果
  → 确认高影响动作
  → 看到结果、错误或下一步
  → 回到相关对象并保留定位
```

## 启动后将页面显示在主显示器

适用于需要在本机启动 HTML 页面、并确保页面窗口出现在主显示器的桌面应用。

- 启动页面时创建独立的浏览器窗口，不要把页面加入用户已有浏览器窗口的新标签中。
- Windows 优先为 Chrome 启动新窗口，并请求窗口最大化。Chrome 已运行时也必须创建新窗口。
- 在打开页面前记录已有顶层窗口；页面加载后，根据页面标题或其他唯一标识找到本次新建的窗口。只移动该窗口，避免影响用户原先打开的浏览器窗口。
- 将窗口移至主显示器的工作区后再最大化，确保最大化发生在主显示器上。可通过 Windows 窗口 API 获取主显示器工作区、定位窗口并执行最大化。
- 若目标浏览器未安装，使用系统默认浏览器的新窗口模式，并对新窗口执行同样的定位和最大化流程。
- 其他平台使用系统默认浏览器打开页面；可使用平台提供的窗口管理能力实现主显示器定位。
- 如果无法启动浏览器或无法找到新窗口，应记录清楚的日志，并保留可手动访问的页面地址。

## 需要在后续项目中共同决定的事项

1. 默认入口是任务选择页、数据列表，还是按角色提供不同入口？
2. 哪些操作适合直接在列表完成，哪些必须进入详情或专门流程？
3. 哪些自动化结果可直接保存，哪些必须人工检查？
4. 哪些动作需要二次确认、撤销或退回机制？
5. 用户需要看到哪些进度细节：阶段、百分比、预计耗时，还是仅结果状态？
6. 窄屏是否属于主要使用场景？若是，哪些桌面交互必须重新设计？
7. 是否需要统一全局状态徽标、成功/失败提示、空状态和错误文案规范？

## 归纳

可复用的核心不是某个固定页面，而是一组稳定关系：入口让目标清楚，主视图便于定位，详情提供上下文，自动化结果可被检查，高影响操作有明确确认，处理过程和结果持续可见，完成后仍能回到相关工作位置。
